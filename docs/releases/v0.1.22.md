Jarvis 0.1.22 fixes desktop startup, local AI reliability, and native service responsiveness.

## Changes

- Fix renderer hydration failure caused by a Node crypto import in browser code.
- Replace production port/timer guessing with HTTP readiness checks, bounded startup, recovery UI, and retry.
- Make authentication asynchronous, defer heavy native modules, bound IPC waits, and prevent overlapping telemetry requests.
- Keep Ollama discovery off the startup path; report offline/errors truthfully, discover exact model tags, and handle streaming/cancellation correctly.
- Fix memory serialization/vector queries, home-folder shortcuts, chat sizing, and close-to-tray behavior.
- Reduce continuous wallpaper rendering and generated-output watcher activity.
- Align source, installer, tag, and updater versions; refresh documentation and release checks.

## Verification and limits

Six regression tests, renderer/Electron type checks, lint (zero errors), and production builds passed during stabilization. Native checks covered development mode, repeated production launches, 21 routes, actual Ollama chat, offline startup, file/memory IPC, minimize/restore, and intentional renderer crash recovery. See [STABILIZATION.md](https://github.com/ehtisham5618/Jarvis-OS/blob/v0.1.22/STABILIZATION.md) for measurements and release-specific verification.

Windows 10/11 x64. Install `Jarvis-Setup-0.1.22.exe`. Ollama and models are installed separately; no automatic model download occurs at startup. Semantic retrieval needs an embedding model. Some sensors and dashboard content have documented limitations. Voice, Windows Hello, plugins, and every automation were not exhaustively tested.

The original historical Windows Not Responding event was not conclusively reproduced; identified blocking hazards were repaired and completed smoke tests recorded no unresponsive-window event. Builds without a configured signing certificate are unsigned. Resources are packaged without ASAR.
